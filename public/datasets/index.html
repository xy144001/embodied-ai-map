DATA FORMAT

数据格式与组织方式

下面四项并不处于同一层级：RLDS 和 LeRobot 更接近数据组织规范与加载生态，HDF5 是文件容器，ROS bag / MCAP 是机器人原始消息日志。一个数据集可能同时使用其中两项。

Episode机器人完成一次任务尝试的完整序列，例如从拿起杯子到放到指定位置。
Step序列中的一个时间点，通常包含当时的观测和机器人执行的动作。
Observation机器人能看到或测到的信息，如相机、关节、IMU、足底力和物体状态。
Action发送给控制器的命令，如关节目标、关节力矩或手脚末端位姿。
名称它属于什么数据如何组织什么时候使用
RLDS / TFDS 说明 ↗顺序决策数据规范 / TensorFlow数据生态一个episode包含多个step，每步保存observation、action等字段统一多个机器人数据集并供TensorFlow训练；仍需核对动作语义
LeRobot v3 说明 ↗数据集规范、加载工具与发布生态Parquet存状态和动作，MP4存视频，metadata记录字段和统计适合PyTorch训练、Hugging Face发布和大规模流式加载
HDF5 / robomimic 说明 ↗通用二进制文件容器 / 机器人学习字段约定在一个或多个文件中集中保存数组、episode和元数据适合中小规模模仿学习；数据很大时需要合理分片
ROS bag / MCAP 说明 ↗机器人运行时的原始消息日志按时间保存相机、关节、IMU、力传感器等不同话题适合采集留档；训练前还要同步、切episode并转换格式
WebDataset 说明 ↗基于 Tar 分片的流式数据格式样本按键组织在多个 .tar shard 中，可边下载边迭代读取视频与状态适合大规模 VLA 预训练；如果需要随机访问、按 episode 修改或跨模态同步，则需要额外设计。
高频多模态时间同步

人形机器人常同时记录视觉约30 Hz、关节约500 Hz、力/触觉约1 kHz。必须保留硬件时间戳、时钟来源、同步误差和缺帧策略，不能只按文件顺序拼接。

触觉与音频不是“附加文件”

电子皮肤、足底压力、麦克风和语音指令应记录采样率、坐标系、校准状态及与主 episode 的时间关联；否则训练时很难判断接触或语音何时发生。

标准与数据治理层

行业或团体标准通常规定数据安全、脱敏、标注和编码要求，它们与 HDF5、RLDS 等文件格式是两层概念。采用具体 SJ/T、T/SAIAS 等标准前，应以正式发布版本和适用范围为准。

跨格式转换时需要保留什么

把不同来源的数据接入统一训练管线时，经常要对齐频率、改变动作表示或做人到机器人的动作映射。下面三类问题说明转换过程中可能丢失哪些 Full-body 信息。

多频率传感器 → 统一 step

Full-body数据常同时包含低频相机和更高频的IMU、关节、足底力。简单降到同一低频率，可能遗漏落脚冲击、失衡和接触变化。

全身关节动作 → 手脚末端位姿

如果只保留手或脚到达的位置，会丢失膝、髋、躯干的协调方式和关节限制，难以复原原始全身动作。

人体动作 → Humanoid动作

人体与机器人在骨骼比例、关节范围和接触条件上不同，需要同时保存原始人体动作、retarget结果以及接触和修正信息。

DATA LIFECYCLE

从采集到验证的数据闭环

这不是一次性流水线：评测会暴露任务、场景、失败状态或传感信息的缺口，再回到采集、清洗和标注环节补充数据，随后重新训练与评测。

  1. 01采集 / 生成
  2. 02同步与标定
  3. 03清洗与切分
  4. 04标注
  5. 05质量控制
  6. 06格式统一
  7. 07数据划分
  8. 08训练
  9. 09评测 / 诊断 / 回流
持续迭代评测结果驱动下一轮数据更新

每轮训练结束后，不只看总分，还要定位模型在哪些任务、场景、状态或身体接触上失败。

  1. 01评测与诊断按任务、场景和失败类型拆解结果
  2. 02定位数据缺口判断缺的是覆盖、质量、标注还是格式
  3. 03补充采集与处理采新数据，或重新清洗、切分和标注
  4. 04更新版本并重训记录版本差异，再进入下一轮评测

常见现状

现有公开数据通常有什么

  • RGB、机器人状态、动作和episode划分较常见
  • 时间戳、控制频率和标定完整度差异较大
  • 语言、失败原因和人工干预标签并不普遍
  • Full-body的足底接触、根部状态和恢复数据尤其稀缺
最低必需

让一条episode可解释

  • 时间戳与episode边界
  • 观测、可执行动作与控制模式
  • 本体、关节、坐标系和标定
  • 任务结果、来源、版本和许可
任务加分

让数据更有研究价值

  • 语言、技能阶段与失败原因
  • 力、触觉、接触和人工干预
  • 操作者、固件和标定质量
  • 扰动、恢复和安全事件
Full-body 必需

让全身协调没有被格式抹掉

  • 根部姿态、IMU与全身关节
  • 足底接触、躯干与质心代理
  • 手物状态、负载和接触
  • 安全中止、失衡与恢复原因
